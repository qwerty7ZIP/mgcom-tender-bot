# mgcom_nb_bot

Telegram-бот, который ежедневно (по умолчанию в 11:00 и 17:00 МСК) присылает
менеджерам их **просроченные сделки** из Google-таблицы. Под полем ввода — кнопки
для запроса актуальных данных в любой момент.

Google Cloud / API-ключи **не нужны**.

## Архитектура

Все данные (**просроченные сделки** и **принятие решения**) бот берёт из
Google-таблицы через Apps Script (push-модель): скрипт по таймеру обновляет
листы из CRM и шлёт снапшот на `POST /ingest`, бот хранит его в
`data/snapshot.json` и читает при нажатии кнопок и перед авторассылкой.

```
Apps Script (по таймеру) ──► CRM ──► листы Google ──► POST /ingest ──► Бот (VPS)
Кнопка / триггер 11:00,17:00 ──► Бот читает снапшот ──► Telegram
```

- Листы в снапшоте: `PRIMARY_SHEET` (просрочка) и `DECISION_SHEET` (принятие
  решения) — их имена перечислены в `SHEET_NAMES` в `apps_script/Code.gs`.
- Google Cloud / публичный web-app не нужны: скрипт работает под твоей учёткой
  и сам шлёт данные боту.

## Логика отчёта

- Колонки листа: `ID | Название | Постановщик | Дата окончания | Ссылка`.
- Просроченная сделка = `Дата окончания` строго раньше сегодняшней даты (по TZ).
- Название сделки оформляется гиперссылкой на `Ссылка` (как на образце).
- Времена авторассылки задаются в `SEND_TIMES` (по умолчанию `11:00,17:00`).

### Роли (поле `role`)

- **manager** (по умолчанию): получает только свои сделки (где он указан в
  `Постановщик`). В авторассылку — **одно** сообщение (просроченные).
  Кнопка под полем ввода — «Мои просроченные».
- **head** и **admin**: 4 кнопки под полем ввода —
  «Мои просроченные» (просрочка по своему `setter`),
  «Все просроченные» (общий список по всем менеджерам),
  «Мои решения» (принятие решения по своему `setter`),
  «Все решения» (весь лист принятия решения).
  У **admin** под сообщением «Все просроченные» дополнительно есть инлайн-кнопки
  по каждому менеджеру (подпись = `setter`) — нажатие присылает сделки этого
  менеджера. В авторассылку: **admin** — все просроченные + все решения;
  **head** — свои просроченные + свои решения. Источник просрочки —
  `PRIMARY_SHEET`, решений — `DECISION_SHEET` (по умолчанию «Принятие чистка»).

> Apps Script шлёт оба листа (`PRIMARY_SHEET` и `DECISION_SHEET`) одним снапшотом —
> их имена перечислены в `SHEET_NAMES` в `apps_script/Code.gs`.

## Настройка

### 1. Бот (VPS)

1. Создай бота у [@BotFather](https://t.me/BotFather), получи `BOT_TOKEN`.
2. Скопируй `.env.example` в `.env` и заполни:
   - `BOT_TOKEN`
   - `INGEST_TOKEN` — длинный случайный секрет (`openssl rand -hex 32`),
     нужен для приёма снапшота таблицы от Apps Script.
   - Список пользователей — двумя способами:
     - **файл `users.json`** (рекомендуется, читаемый многострочный JSON; см.
       `users.json.example`). Монтируется в контейнер через `docker-compose.yml`.
     - либо `USERS_JSON` одной строкой в `.env` (имеет приоритет, если задан).

     Поля: `login` = ТГ-логин без @, `setter` = значение в колонке «Постановщик»
     (обязательно для `manager`/`head`), `greeting` — необязательно,
     `role` = `manager`/`admin`/`head` (по умолчанию `manager`).
3. Открой порт `INGEST_PORT` (по умолчанию 8080) в firewall VPS, чтобы Apps Script
   мог достучаться. **Рекомендуется** поставить перед ботом HTTPS-прокси
   (Caddy/Nginx), чтобы токен не ходил открытым текстом.

### 2. Apps Script (внутри таблицы)

1. В таблице: **Расширения → Apps Script**, вставь код из
   [`apps_script/Code.gs`](apps_script/Code.gs).
2. Укажи `INGEST_URL` (адрес эндпоинта `/ingest` твоего VPS, по `http://`),
   `INGEST_TOKEN` (тот же, что в `.env`) и `SHEET_NAMES` — список листов для
   отправки (по умолчанию `['Просрок чистка', 'Принятие чистка']`).
3. Запусти функцию `pushSnapshot` вручную один раз — выдай Google запрошенные
   разрешения.
4. Запусти функцию `createTrigger` один раз — создастся таймер (каждые 5 минут).

### 3. Подписка менеджеров

Каждый менеджер из whitelist один раз пишет боту `/start` — так бот узнаёт его `chat_id`.

## Запуск (Docker Compose)

```bash
docker compose up -d --build
docker compose logs -f
```

- `chat_id` подписчиков → `./data/subscribers.json`, снапшот таблицы → `./data/snapshot.json`
  (том, переживают перезапуск).
- Проверка живости: `GET http://<vps>:8080/health` → `ok`.

## Команды бота

- `/start` — подписаться на ежедневную сводку.
- `/deals` — показать актуальные просроченные сделки прямо сейчас (с кнопкой «Обновить»).
