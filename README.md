# mgcom_nb_bot

Telegram-бот, который раз в день (по умолчанию 11:00 МСК) присылает каждому менеджеру
его **просроченные сделки** из Google-таблицы. Под сообщением — кнопка «🔄 Обновить»,
которая в течение дня перезапрашивает актуальные данные.

Google Cloud / API-ключи **не нужны**.

## Архитектура (push-модель)

Таблица **Deal checker 2026** доступна только домену MGCom — её нельзя открыть
анонимно, поэтому бот не может читать данные у Google напрямую. Решение —
развернуть поток наоборот:

```
Google Sheets ──(Apps Script, от твоего имени)──► POST /ingest ──► Бот (VPS) ──► Telegram
                 раз в 5 минут, push                            хранит снапшот,
                                                                рассылает в 11:00 + по кнопке
```

- **Apps Script** работает внутри Google от твоего имени (доступ к таблице есть)
  и по таймеру шлёт снапшот листа на эндпоинт бота. Развёртывание Web App не нужно —
  используются только исходящие запросы, которые домен не ограничивает.
- **Бот** на VPS принимает снапшот, сохраняет в `data/snapshot.json` и из него
  рассылает сообщения. Свежесть данных по кнопке «Обновить» = последний push (≤5 мин).

## Логика отчёта

- Колонки листа: `ID | Название | Постановщик | Дата окончания | Ссылка`.
- Просроченная сделка = `Дата окончания` строго раньше сегодняшней даты (по TZ).
- Название сделки оформляется гиперссылкой на `Ссылка` (как на образце).

### Роли (поле `role` в `USERS_JSON`)

- **manager** (по умолчанию): получает только свои сделки (где он указан в
  `Постановщик`). Кнопка под полем ввода — «Мои просроченные».
- **admin**: получает общий список просроченных сделок по всем менеджерам,
  сгруппированный по постановщикам, и инлайн-кнопки по каждому менеджеру
  (подпись = `setter`) — нажатие присылает сделки конкретного менеджера.
  Кнопка под полем ввода — «Все просроченные». Поле `setter` для админа
  можно не указывать.
- **head** (Руководитель): как `manager` (своя просрочка из листа
  `PRIMARY_SHEET`), плюс кнопка «Принятие решения» — список всех сделок из листа
  `DECISION_SHEET` (по умолчанию «Принятие чистка») в виде гиперссылок.

> Apps Script шлёт оба листа (`PRIMARY_SHEET` и `DECISION_SHEET`) одним снапшотом —
> их имена перечислены в `SHEET_NAMES` в `apps_script/Code.gs`.

## Настройка

### 1. Бот (VPS)

1. Создай бота у [@BotFather](https://t.me/BotFather), получи `BOT_TOKEN`.
2. Скопируй `.env.example` в `.env` и заполни:
   - `BOT_TOKEN`
   - `INGEST_TOKEN` — длинный случайный секрет (`openssl rand -hex 32`).
   - `USERS_JSON` — список пользователей (`login` = ТГ-логин без @, `setter` =
     значение в колонке «Постановщик», `greeting` — необязательно,
     `role` = `manager`/`admin` — необязательно, по умолчанию `manager`).
3. Открой порт `INGEST_PORT` (по умолчанию 8080) в firewall VPS, чтобы Apps Script
   мог достучаться. **Рекомендуется** поставить перед ботом HTTPS-прокси
   (Caddy/Nginx), чтобы токен не ходил открытым текстом.

### 2. Apps Script (внутри таблицы)

1. В таблице: **Расширения → Apps Script**, вставь код из
   [`apps_script/Code.gs`](apps_script/Code.gs).
2. Укажи `INGEST_URL` (адрес эндпоинта `/ingest` твоего VPS, по `http://`),
   `INGEST_TOKEN` (тот же, что в `.env`) и `SHEET_NAMES` — список листов для
   отправки (по умолчанию `['Просрок чистка', 'Принятие чистка']`).
3. Запусти функцию `pushSnapshot` вручную один раз — выдай Google запрошенные
   разрешения.
4. Запусти функцию `createTrigger` один раз — создастся таймер (каждые 5 минут).

### 3. Подписка менеджеров

Каждый менеджер из whitelist один раз пишет боту `/start` — так бот узнаёт его `chat_id`.

## Запуск (Docker Compose)

```bash
docker compose up -d --build
docker compose logs -f
```

- `chat_id` подписчиков → `./data/subscribers.json`, снапшот таблицы → `./data/snapshot.json`
  (том, переживают перезапуск).
- Проверка живости: `GET http://<vps>:8080/health` → `ok`.

## Команды бота

- `/start` — подписаться на ежедневную сводку.
- `/deals` — показать актуальные просроченные сделки прямо сейчас (с кнопкой «Обновить»).
